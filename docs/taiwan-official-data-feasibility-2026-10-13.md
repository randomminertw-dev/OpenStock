# 台股官方資料遷移可行性研究

研究日期：2026-10-13。狀態：研究完成，已依使用者零新增費用條件形成待核准設計，尚未修改產品程式碼。

使用者後續決定：官方盤後與歷史資料搭配現有 API／TradingView；任何需要付費的新盤中服務暫不增加，應用以中長期分析為主。最終設計見 `docs/superpowers/specs/2026-10-13-taiwan-official-data-design.md`。下列三方案保留為研究比較，付費盤中方案已不列為本次實作建議。

## 需求與結論

使用者希望解決台股與 ETF 搜尋不到、價格或歷史資料缺漏，同時取得持續更新的盤中價格及完整正確的盤後資料。

依使用者最新條件，建議採用「官方盤後與歷史資料＋既有免費盤中元件＋MongoDB 共用資料庫」。上市使用 TWSE，上櫃使用 TPEx。OpenAPI 作為主要官方資料入口，但不能把所有功能限制在 `openapi.twse.com.tw` 單一網域。

只使用指定 OpenAPI 可以改善上市股票與 ETF 的盤後覆蓋，但無法同時滿足盤中即時價格、既有歷史技術指標、上櫃行情、新聞與社群情緒的完整需求。資料來自官方也不代表不存在缺值、發布延遲或更正。

## 研究方法與實測證據

已讀取現有程式、TWSE 與 TPEx Swagger，並對公開端點進行 GET。測試未帶 API key，未操作正式資料庫，未呼叫寄信功能。以下是單次實測，筆數、日期與耗時會變動，不能當成服務保證。

| 來源 | 結果 | 判讀 |
|---|---|---|
| TWSE Swagger | 143 paths | 資料集多，但不等於每一種資料都有歷史區間查詢 |
| `exchangeReport/STOCK_DAY_ALL` | HTTP 200；1,381 筆；319,784 bytes；約 3.13 秒；日期 `1151012` | 本次為 2026-10-12 行情；日期為民國年 |
| 同端點加 `?date=20260901` | 回應與無參數版本逐 byte 相同 | 本次日期參數未生效；Swagger 亦未宣告日期參數 |
| `opendata/t187ap03_L` | HTTP 200；1,095 筆；約 1.33 MB；約 7.58 秒 | 公司名單不能當成完整證券／ETF 名單 |
| `opendata/t187ap47_L` | HTTP 200；272 筆 | 有基金代號、簡稱、類型、發行單位等 ETF 商品資料 |
| `exchangeReport/BWIBBU_ALL` | HTTP 200；1,083 筆 | PE、殖利率、PB；部分 PE 為空字串，不能轉成 0 |
| 官網 `exchangeReport/STOCK_DAY`：2330、202609 | HTTP 200；`stat: OK` | 可取得月份內逐日日 K；此介面位於 `www.twse.com.tw` |
| 同歷史介面：0050、202609 | HTTP 200；20 根日 K | 已確認 ETF 歷史可取；回應包含分割與反分割註記說明 |
| TPEx Swagger | HTTP 200；225 paths | 上櫃須獨立來源 |
| TPEx `tpex_mainboard_daily_close_quotes` | HTTP 200；12,421 筆；約 4.86 MB；日期 `1151013` | 涵蓋範圍不能直接等同上櫃普通股數；須依商品主檔分類與篩選 |

TWSE 日行情實測找到 `2330`、`0050`、`0056`、`00878`、`00919`、`00940`、`00400A`；找不到上櫃 `6488`，但 TPEx 回應找得到。這證明 ETF 可以由官方來源補齊，也證明上市來源不能取代上櫃來源。

TWSE 與 TPEx 本次發布日期不同，必須保存各來源的資料日期，不能以抓取時間或其他市場日期代替。

本機 curl 首次受網路限制；取得網路權限後實測成功。瀏覽工具部分端點出現錯誤，不能據此宣稱官方服務不可用。尚未從正式部署環境測試 IP 封鎖、持續穩定性、發布時間與盤中延遲。

## 現有程式盤點與影響

| 功能 | 現況 | 遷移方向 |
|---|---|---|
| 日 K 與技術指標 | `lib/candles/providers.ts` 使用 FinMind | 官方歷史補齊＋每日增量；延續 OHLCV 與錯誤原因契約 |
| 市場辨識 | `lib/candles/symbols.ts` 將 TWSE、TPEX 合成 `taiwan` 且只留下代號 | 在供應商分流前保留交易所；不可僅憑代號猜來源 |
| 搜尋 | `searchStocks` 依賴 Finnhub，缺金鑰時提早返回空陣列 | 台股獨立讀官方主檔索引，支援代號、中文簡稱、完整名稱 |
| 股票頁報價 | 台股走 TradingView widget | 自建報價區，盤中與收盤資料明確區分 |
| 自選清單 | 不支援 Finnhub 報價的商品回傳價格 0、預設 USD | 共用市場報價路由；缺值為 null，幣別由商品資料決定 |
| 價格提醒 | 背景工作直接呼叫 Finnhub `getQuote` | 接同一報價路由；依實際行情時效與授權決定台股提醒契約 |
| 圖表 | TWSE 被列為無法嵌入 TradingView K 線 | 官方日 K 自建圖表；日 K 不能替代盤中分 K |
| 技術分析 widget | TradingView，文案含 1h | 已有日 K 指標可重用，但不得保留 1h 語意假裝等價 |
| 公司與財務 | TradingView widget | 官方基本資料、營收、EPS、PE/PB/殖利率與分產業報表 |
| 新聞／社群情緒 | Finnhub、Adanos | 官方重大訊息可新增為獨立資訊類型；不是新聞、社群情緒的等價替代 |
| 市場首頁 | `lib/markets.ts` 尚無 Taiwan MarketId | 若納入此範圍，需增加台股市場入口與原生資料元件 |

ETF 不應顯示不存在的公司營收、EPS 或 PE；應依商品類型顯示基金資料。外幣交易 ETF 不應一律標成 TWD；一般新臺幣交易股票與 ETF 才使用 TWD。不可因缺少當日行情就從搜尋主檔刪除停牌商品。

## 三種方案比較

| 方案 | 優點 | 缺口與成本 | 建議 |
|---|---|---|---|
| A：只用指定 TWSE OpenAPI | 接口集中、上市盤後資料容易批次取得 | 缺歷史區間、上櫃與可依賴的盤中即時服務；需降低功能 | 不符合已確認需求 |
| B：TWSE＋TPEx 官方盤後與歷史接口 | 覆蓋上市、上櫃與 ETF；可支持既有日 K 指標 | 尚未滿足盤中持續更新；官網歷史接口需節流與持久化 | 適合作為底座 |
| C：方案 B＋具授權盤中行情 | 同時支持盤中與盤後，資料可共用 | 須確認供應商覆蓋、授權、延遲、費用與憑證 | 使用者已排除新增付費服務 |

盤中行情可比較官方簽約資訊廠商的服務。直接串接交易所正式即時資訊也是選項，但依官方申請、連線與收費方式，對目前網站可能成本較高；實際費用必須依用途詢價，不以單一收費項目估算總費用。

MIS 網站的內部查詢接口可作研究觀察對象，但目前未驗證穩定性、授權與部署可用性，不建議直接選為正式即時供應商。公開網站能顯示即時價格，不代表其接口具有可供網站再散布的服務契約。

## 建議資料設計

延續 Next.js、TypeScript、MongoDB 與現有 Inngest；不引入新的服務平台。以下為研究者建議，尚未核准實作。

1. 商品主檔：以 `(exchange, code)` 為主鍵，代號保持字串，保留前導零、英文字母、商品類型、名稱、幣別、上市日期與可交易狀態。合併公司、ETF 與行情清單，不以單一清單作內聯接而排除商品。行情中尚未分類的證券先標 unknown，不猜成 ETF 或普通股。
2. 日 K：唯一索引含交易所、代號、交易日、價格基準。來源提供日期、OHLC、成交股數，另存取得時間、版本及完成狀態。依交易日去重，可重抓近期資料覆寫更正。
3. 報價：來源、行情時間、取得時間、盤中／延遲／收盤模式與 stale 狀態分開。既有每日 bar 的午夜 timestamp 不是報價時間。盤中缺資料時可顯示最近收盤，但明示狀態；提醒不把降級收盤值當成即時值。
4. 財務：保存報告年度、季度、產業、累計／單季口徑、單位與來源日期。各產業報表分開映射；缺少現金流或完整歷史時標示資料範圍，不宣稱完整取代原 widget。
5. 來源 metadata：保留 `api-error`、`no-data`、`unsupported-symbol` 等差異，新增來源名稱與時效資料，延續 UI 重試流程。

日 K 與即時報價分開保存；盤中當日資料不能寫成已完成日 K。主檔、報價、OHLCV 與財務都在伺服器端正規化，瀏覽器不自行抓整份官方資料集。

官方數字字串要去逗號，空字串、`--`、不可比價標記與合法零分開處理。民國日期明確加 1911、驗證日期並使用 Asia/Taipei；歷史回應用欄位名定位，避免新增註記欄後位置錯位。檢查價格上下界與量非負，不能拿前日資料補成新的交易日。

先維持現有 unadjusted 日 K 口徑，記錄除權息與 ETF 分割事件並在研究用途顯示提醒；調整價需要獨立設計與驗收，不可只除價格卻留下不一致成交量，也不能混用 FinMind 與官方不同價格基準。

## 同步與效能

行情與主檔批次取得後寫入 MongoDB。搜尋、股票頁、自選與提醒共同讀取，避免每位使用者重抓全市場。現有記憶體 Map 只在單一 process 共用，不能處理多個部署 instance 或重啟。

盤後同步依交易日與實際資料日期判斷完成，定時重試直到更新或逾時；來源尚未發布不能顯示「已同步今天」。初始排程時段需實測發布時間，不能直接把 13:30 當成所有資料集完成時間。主檔／財務依資料集頻率更新。

歷史資料先回填被搜尋、瀏覽或加入自選的商品，按月份低併發排隊，再批次擴大。既有指標通常要求 400 日曆天；四因素另有 warm-up 和 ATR 分位歷史要求，實作前應依最大合法 N 推導完整根數，不能只取得 126 根就宣稱足夠。

估算上市單檔回填 400 日曆天約需 14–15 個月份請求；100 檔約 1,400–1,500 次，1,000 檔約 14,000–15,000 次。這是容量估算，未包含重試；所以不適合在一個頁面請求中全部完成，也不建議一開始就回填所有權證。

限流、退避、timeout、分散式工作去重與保留最後成功資料是必要部分。限流值由官方說明與低流量觀測決定，目前未找到可作保證的每分鐘額度或 SLA，不填入猜測值。盤中上游更新頻率、頁面輪詢頻率與現有每 5 分鐘提醒工作的頻率須分別定義。

## 分期與驗收

1. 官方商品搜尋與盤後報價：先解決 ETF／台股找不到、價格顯示 0 與幣別錯誤。既有 `.TW`、`.TWO`、`TWSE:`、`TPEX:` 連結保留，建立別名映射，不直接改寫使用者自選資料。
2. 官方歷史日 K 與指標：上市與上櫃分流、背景回填、來源與日期顯示；上櫃歷史端點尚需單獨實測，完成前不宣稱已驗證。
3. 具授權盤中行情：先以 2330、0050、上櫃股票與上櫃 ETF 驗證，再接報價、自選、提醒。服務選定前此期不能估定費用或承諾秒級延遲。
4. 自建台股圖表、公司／ETF 詳情、估值與公告：逐一替換台股 widget，對不能等價替代的社群／新聞功能確認保留或調整。

驗收至少包括上述六檔 ETF／股票、6488、另一檔經主檔確認的上櫃 ETF、外幣 ETF、停牌、無成交、新上市與未知代號；別名查詢一致；不受 Finnhub key 有無影響；普通股與 ETF 顯示不同資料。

歷史驗收核對來源逐日 OHLCV、休市缺口、400 日曆天範圍、資料更正及 ETF 分割；不足歷史保持 N/A。技術評分維持已核准口徑，台股不得新增 SPY 尾端錯位比較。

盤中驗收必須從實際部署環境在開盤、交易中、收盤與休市觀察行情 timestamp、stale、重試及來源覆蓋。價格提醒按供應商延遲與排程頻率驗收，不承諾每一筆成交都被捕捉。

遷移驗證使用 mock provider 測試、跨市場回歸與必要 build/lint。比較過渡期間 FinMind 與官方同日資料的差異，留存原因；最終移除台股 FinMind 路徑前確認回填與部署驗收完成，不靜默混用兩個來源。

## 使用者後續決定與研究者建議

- 不新增付費盤中服務，沿用現有免費範圍；未支援商品顯示最近官方收盤日期與來源。
- 中長期分析優先，官方日 K 不混入盤中未完成資料。
- 研究者建議保留既有新聞／社群來源；本次聚焦現有台股頁、搜尋與自選，不新增台股市場首頁。
- 部署前核對現有基礎設施免費配額；不足則減少同步或採本機手動同步，不能自動升級或承諾永久零成本。
